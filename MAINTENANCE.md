# Maintenance & Configuration Guide

This file explains how the profile is put together and exactly what to edit as things change. It is not shown to visitors — it's for future-you.

## 1. Folder structure

```
lucifer-1589/                  (repo name must match your GitHub username exactly)
├── README.md                  Rendered on your GitHub profile page
├── MAINTENANCE.md             This file
└── assets/
    ├── banner-hero.svg        Custom animated hero banner (AI + Security + Cloud motif)
    └── section-divider.svg    Reusable animated separator used between sections
```

**One-time setup:** create a repository named exactly `lucifer-1589` (must match your username), push these files to its default branch, and GitHub will render `README.md` on your profile automatically. No build step, no CI required.

## 2. What's real vs. what's a placeholder

Everything under **GitHub Analytics** (stats card, top languages, streak, activity graph, trophies) and the **Profile Views / Followers** badges in the header pull **live data** from your account via public read-only services. There is nothing to configure there beyond keeping the username `lucifer-1589` correct in each URL.

Everything wrapped in `` `[Add ...]` `` brackets is a placeholder you should replace as the real information exists — repo links, live demo links, tech stacks per project, roadmap items, certification status. Don't leave brackets in place once you have the real content; an unresolved placeholder reads worse than an honest "in development."

### 3a. Why the Stats/Languages card is self-hosted

The original card used the shared public instance at `github-readme-stats.vercel.app`, which is maintained for free and frequently hits Vercel's hobby-tier bandwidth cap — it was returning `DEPLOYMENT_PAUSED` (HTTP 503) as of 2026-07-22, a known recurring issue for that specific shared instance, unrelated to anything in this repo. `github-profile-trophy.vercel.app` had the same problem (`DEPLOYMENT_DISABLED`, HTTP 402), which is why Trophies now points at the still-live `github-trophies.vercel.app` deployment of the same project instead.

For Stats/Languages there was no equivalent live alternate instance, so it's generated locally instead via the [`lowlighter/metrics`](https://github.com/lowlighter/metrics) GitHub Action, which runs entirely inside this repo's own Actions and commits a static SVG — no dependency on anyone else's server, ever.

**One-time setup required** (I can't do this step for you — it's a repo-owner-only setting):
1. Go to this repo's **Settings → Actions → General → Workflow permissions**.
2. Select **"Read and write permissions"** and save. (Default is read-only, which would make the workflow fail with a permissions error when it tries to commit the generated SVG back.)
3. Go to the **Actions** tab → **Profile Metrics** workflow → **Run workflow** once, to generate it immediately instead of waiting for the next 03:30 UTC scheduled run.

Until that first successful run, `assets/github-metrics.svg` shows a small "generating…" placeholder instead of a blank/broken image. After it runs, the workflow keeps it fresh automatically (daily cron + on every push to `main`) with no further action needed.

If `github-trophies.vercel.app` or the streak/activity-graph hosts ever go down too, the same self-hosting pattern (a scheduled Action committing a static SVG into `assets/`) is the durable fix — ask for it to be added the same way.

## 4. Adding a new featured project

Copy the block for an existing project card in `README.md` (the `### emoji Project Name` section through the closing `---`), and:
1. Replace name, description, and emoji.
2. Fill in Tech Stack, Repository, Live Demo, Status.
3. Once the repo is public, replace the Stars placeholder with:
   `![GitHub Repo stars](https://img.shields.io/github/stars/lucifer-1589/REPO_NAME?style=social)`
4. Only keep the Mermaid architecture diagram if it's worth showing — don't force one for simple projects.

## 5. Updating certifications

The certifications table uses a `Status` column (`Planned` / `In Progress` / `Earned`). When you actually earn one, change the status and optionally add the official badge image (most providers — AWS, Microsoft, Google — give you an embeddable badge URL from your certification dashboard).

## 6. Connecting the Writing/Blog section

The `<!-- BLOG-POST-LIST:START -->` / `END` markers in `README.md` are the exact format expected by the **blog-post-workflow** GitHub Action, which auto-updates that list on a schedule:

https://github.com/gautamkrishnar/blog-post-workflow

To enable: add a workflow file under `.github/workflows/` in this repo pointing at your blog's RSS feed (Dev.to, Medium, Hashnode, or a personal blog feed all work), following that action's README. Until you have a blog, leave the placeholder line as-is.

## 7. Editing the custom SVGs

Both `assets/banner-hero.svg` and `assets/section-divider.svg` are hand-written, commented SVG — no build tools involved. Open them in any editor:
- Colors are centralized in each file's `<defs>` gradient stops (`#00e5ff` cyan, `#8a5cf6` violet, `#ff5c8a` pink) — change those three hex values to re-theme both files consistently.
- Animations use native SMIL (`<animate>`, `<animateMotion>`) so they play in any browser without JavaScript, including when embedded as a plain `<img>` in the README.
- Keep dimensions (`viewBox`) unchanged if you only want to recolor; resize the `width="100%"` on the `<img>` tag in `README.md` instead of editing the SVG's intrinsic size.

## 8. Light/dark mode

The stat widgets above are set to a dark (`tokyonight`/`onedark`) theme, matching the neon hero banner — this looks intentional in both GitHub light and dark viewing modes since the images themselves have a fixed dark card background, same as most trending profiles. If you want the stat cards to actually swap with the viewer's OS theme, wrap each `<img>` in a `<picture>` element with a `prefers-color-scheme` media query pointing at a second, light-themed URL (e.g. `theme=default` for github-readme-stats) — the services above all support that.
